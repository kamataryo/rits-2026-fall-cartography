## 地図はどうやって届くのか？

- 世界中の地図を一度に送ると、データが大きすぎる
- => 地図を小さな正方形（**タイル**）に分けて、**今見えている場所のタイルだけ**を送る

### タイルの仕組み

1. **分割**: 地図を 256 × 256 ピクセルの正方形に分ける（512 ピクセルのものも多い）
2. **階層化**: ズームレベルごとに、細かさの違うタイルを用意する
3. **配信**: 必要なタイルだけを、必要なときにダウンロードする
4. **表示**: タイルを敷き詰めて、1枚の地図に見せる

---

## ズームレベルとタイル数

ズームが1上がるごとに、1枚のタイルが縦横に2分割される（= 4枚になる）

- **ズーム 0**: 世界全体を1枚
- **ズーム 1**: 4枚
- **ズーム 2**: 16枚
- **ズーム n**: 4<sup>n</sup> 枚

https://kamataryo.github.io/vector-grids/ で見てみよう

---

## 計算してみよう

1. ズームレベル 10 のタイルは、何枚？
2. ズームレベル 0〜10 のタイルは、合計何枚？

---

## 答え

1. 4<sup>10</sup> = **1,048,576 枚**（約100万枚）
2. 1 + 4 + 16 + … + 4<sup>10</sup> = **1,398,101 枚**（約140万枚）

=> 全部をまとめて送るのは無理。だから「今見えている分だけ」を送る

## タイルの住所: Z/X/Y

```text
https://tile.openstreetmap.org/{z}/{x}/{y}.png
```

- **Z**: ズームレベル
- **X**: 横方向の番号（西 → 東に増える）
- **Y**: 縦方向の番号（北 → 南に増える）

## ラスタタイルとベクトルタイル

| | ラスタタイル | ベクトルタイル |
|--|--|--|
| **中身** | 画像（PNG、JPEG） | 点・線・面のデータ（PBF） |
| **描画** | サーバーで描画済み | ブラウザで描画 |
| **見た目** | 変えられない | 色や表示を自由に変えられる |
| **地図の回転** | 文字も一緒に回る | 文字は読める向きのまま |
| **扱いやすさ** | 簡単 | 仕組みが複雑 |
| **例** | OpenStreetMap の標準タイル、地理院タイル | OpenFreeMap、地理院地図Vector |

ベクトルタイルの中身は、後の回で詳しく扱います

## MapLibre GL JS

- ウェブページに地図を表示するための、オープンソースの JavaScript ライブラリ
- ラスタタイル・ベクトルタイル・GeoJSON を重ねて表示できる
- 2020年に Mapbox GL JS のライセンスが変わったとき、コミュニティがオープンソース版として引き継いだ（フォーク）
- ベースマップの見た目は **style**（JSON）で決まる

## ウェブ地図は HTML ファイルとして作る

- ウェブページの正体は、**HTML** というテキストファイル（例: `index.html`）
- **作る**: HTML ファイルに、地図を置く場所と、地図を描く命令（JavaScript）を書く
- **見る**: そのファイルを**ブラウザで開く**と、ブラウザが命令を実行して地図を描く

```html
<!-- 地図を置く場所 -->
<div id="map"></div>
<!-- MapLibre GL JS を読み込む -->
<script src="https://.../maplibre-gl.js"></script>
<!-- 地図を描く命令 -->
<script>
  new maplibregl.Map({ container: 'map', style: '...', center: [135.72, 35.03] })
</script>
```

=> 今日 AI に作ってもらうのは、この **HTML ファイル**

## AI に頼むときのコツ

- **具体的に**: 場所、ズーム、使うライブラリを伝える
- **1回に1つずつ**: 一度にたくさん頼まず、動くのを確かめながら進める
- **エラーはそのまま渡す**: 地図が出ないときは、開発者ツールの Console に出たエラーをコピーして AI に貼る
- **わからないところは聞く**: 「この行は何をしている？」と AI に説明してもらう

## ベースマップを使うときの注意

- OpenStreetMap の標準タイルは寄付などで運営されていて、負荷の大きい使い方は禁止されている（[タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)）
- AI が **API キー**の必要な地図サービス（`YOUR_API_KEY` など）を使ったら、キーの要らないものに替えてもらう
- どのタイルを使うときも、**利用規約と出典表記**を確認する

---

## うまくいかないとき

原因を自分で当てなくてよい。**なぜうまくいかないのかを、AI に聞く**

1. **期待と実際を伝える**
   「〜になるはずなのに、〜になっている」
2. **手がかりを渡す**
   Console のエラー、画面のスクリーンショット
3. **「直して」の前に「なぜ？」と聞く**
   「なぜこうなるのか、原因を説明してください」
4. **直ったら、自分の目で確かめる**

=> 原因の説明を読んでおくと、次に同じことが起きたときに自分で気づける

## まとめ

- ウェブ地図は **ベースマップ + オーバーレイ + UI** を重ねてできている
- ベースマップは**タイル**に分けられ、見えている分だけが届く（Z/X/Y）
- ラスタタイルは画像、ベクトルタイルはブラウザで描くデータ
- MapLibre GL JS のコードは AI に書いてもらい、**今日の知識で確かめる**
