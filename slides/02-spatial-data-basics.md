### 空間データの定義

### 空間データを構成するもの

- **属性情報**: 名前・種類・特性・研究データなどの付加情報

## 緯度・経度について

- **緯度（Latitude）**: 赤道を基準とした南北の角度（-90° ～ +90°）
- **経度（Longitude）**: 本初子午線を基準とした東西の角度（-180° ～ +180°）
- 注意: ウェブ地図の世界では、
  - 北緯と東経は + で表されている
  - 南緯と西経は - で表されている

**実習**: 以下の2つのアプリで緯度経度がどのように定められているか確認してみてください。

## 補足: しかし「ジオメトリ」の意味はもっと広い

GeoJSON が扱うのは便利な最小限の型にすぎない。  
数学的に言えば「ジオメトリ = 形」であり、次のようなものもありうる。

- **円・楕円・扇形**
- **曲線（二次関数、放物線、多項式曲線..）**
- **立体（球、円錐、四角柱、..）**

「ジオメトリ」という言葉はもっと広い概念を含んでいることに留意

### 空間データの例

#### 自然地物
- **山**: 標高点（ポイント）、等高線（ライン、あるいはポリゴン）

#### 人工地物
- **交通**: 道路・線路（ライン）
- **農業**: 農地・圃場（ポリゴン）
- **施設**: 敷地（ポリゴン）、店舗・学校（ポイント）

## ジオメトリの基礎

### 基本的なジオメトリタイプ

#### 1. ポイント（Point）
- **定義**: 0次元の幾何学的オブジェクト
- **表現**: 単一の座標点
- **用途**: 店舗、駅、観光地、事故地点など
- 座標は **[経度, 緯度]** の順

```json
{
  "type": "Point",
  "coordinates": [135.5, 34.7]
}
```

---

#### 2. ライン（LineString）
- **定義**: 1次元の幾何学的オブジェクト
- **表現**: 複数の座標点を結んだ線
- **用途**: 道路、河川、境界線、ルートなど

```json
{
  "type": "LineString",
  "coordinates": [
    [135.5, 34.7],
    [135.6, 34.8],
    [135.7, 34.9]
  ]
}
```

---

#### 3. ポリゴン（Polygon）
- **定義**: 2次元の幾何学的オブジェクト
- **表現**: 閉じた線で囲まれた領域
- **用途**: 建物、行政区域、土地利用、湖沼など

```json
{
  "type": "Polygon",
  "coordinates": [[
    [135.5, 34.7],
    [135.6, 34.7],
    [135.6, 34.8],
    [135.5, 34.8],
    [135.5, 34.7]
  ]]
}
```

## 地理座標系と投影法

### 地理座標系
- 地球上の位置を **緯度・経度（角度）** で表す仕組み
- 地球の形（楕円体）の決め方によって、同じ地点でも座標が少しずれる
- ウェブ地図・GPS・GeoJSON では **WGS84**（EPSG:4326）が標準
  - 日本の公的な測量では JGD2011 が使われる（WGS84 とほぼ同じ）

### 投影座標系
- 緯度・経度を **平面上の x, y（メートルなど）** に変換したもの
- ウェブ地図の表示では **Web メルカトル**（EPSG:3857）が標準

👉 データは緯度経度（WGS84）で持ち、表示するときに平面へ投影する

---

### 投影法

#### なぜ投影が必要か？

- 地球は球体（楕円体）
- 地図は平面
- 球面を平面に変換する際に必ず歪みが生じる

---

### Web地図で使用される投影法

#### Web メルカトル図法
- **特徴**: 
  - 角度（狭い範囲の形）が正しく保たれる
  - 世界を正方形に収められるので、タイル分割に適している
  - 高緯度地域で面積が大きく歪む
  - 北緯・南緯約85度より極側は表示できない

## OpenStreetMap データの構造

OpenStreetMap（OSM）のデータは、3種類の **要素** と **タグ** でできている

| 要素 | 内容 | ジオメトリとの対応 |
| --- | --- | --- |
| **ノード（node）** | 緯度・経度を持つ点 | ポイント |
| **ウェイ（way）** | ノードをつないだ線 | ライン（閉じればポリゴン） |
| **リレーション（relation）** | 要素のまとまり | 穴のある面・バス路線など |

👉 OSM は GeoJSON とは別の形式。使うときは変換する（第3-4回で扱います）

---

## タグ（属性情報）

- 各要素には `キー=値` の形で **タグ** がつけられる
- タグによって「それが何か」が決まる

| 例 | 意味 |
| --- | --- |
| `amenity=cafe` | カフェ |
| `building=yes` | 建物 |
| `highway=residential` | 住宅街の道路 |
| `name=京都駅` | 名前 |

タグの意味は [OSM Wiki の Map features](https://wiki.openstreetmap.org/wiki/JA:Map_Features) で調べられる

---
